## 1. 월별 정산 처리

매월 초(1일)에 다음 순서로 정산이 진행된다.

### 1.1 임대료 수익 입금
- 보유 건물에서 월간 임대 수익 발생
- 계산: `건물 현재가 × (연간 임대 수익률 / 12)`

### 1.2 대출 이자 차감
- 보유 대출에 대한 월간 이자 차감

### 1.3 관리비/세금 차감
- 보유 건물에 대한 월별 관리비 및 세금 차감

---

## 2. 매수 프로세스

```
[플레이어] 건물 클릭
    ↓
[UI] 건물 상세 정보 표시
    ↓
[플레이어] "매수" 버튼 클릭
    ↓
[거래 시스템]
    - 플레이어 현금 확인 (가격 + 취득세)
    - 충분하면 거래 실행
    - 현금 차감
    - 건물 소유권 이전
    ↓
[업데이트]
    - Player.buildings에 추가
    - Building.owner = "player"
    - UI 갱신
```

### 매수 조건
- 플레이어 현금 >= 건물 가격 + 취득세
- 건물이 매물 상태 (`is_for_sale == True`)

## 3. 매도 프로세스

```
[플레이어] 보유 건물 클릭
    ↓
[UI] 건물 상세 정보 + "매도" 버튼 표시
    ↓
[플레이어] "매도" 버튼 클릭
    ↓
[거래 시스템]
    - 현재 시세로 매도 실행
    - 양도세 차감
    - 현금 입금
    - 건물 소유권 반환
    ↓
[업데이트]
    - Player.buildings에서 제거
    - Building.owner = "market"
    - UI 갱신
```

## 4. 시세 변동 프로세스

매월 초, 모든 건물의 시세가 재계산된다.

```
[매월 초]
    ↓
[시세 변동 시스템]
    - 각 건물 순회
    ↓
[계산]
    1. 기본 변동률 적용 (-2% ~ +3%)
    2. 지역 트렌드 적용
    3. 환경 요인 적용 (지하철, 한강 등)
    4. 이벤트 효과 적용
    ↓
[업데이트]
    - Building.current_price 갱신
```

### 시세 변동 요인
| 요인 | 설명 | 범위 |
|------|------|------|
| 기본 변동률 | 랜덤 변동 | -2% ~ +3% |
| 지역 트렌드 | 지역별 고유 추세 | [04_regions.md](04_regions.md) 참조 |
| 환경 요인 | 지하철, 한강 등 인접 시설 | [04_regions.md](04_regions.md) 참조 |
| 이벤트 효과 | 발생한 이벤트에 의한 변동 | [06_events.md](06_events.md) 참조 |

---

## 5. 파산 조건

- **조건**: 현금 < -5억원
- **체크 시점**: 매월 초 정산 완료 후
- **결과**: 게임 오버 상태 전환
