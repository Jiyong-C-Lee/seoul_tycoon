> **목적**: 건물 매수/매도의 상세 로직, UI 플로우, 검증 규칙을 정의

---

## 📋 개요

이 문서는 다음 거래 시스템을 정의합니다:

1. **매수 시스템** - 건물 구매 프로세스
2. **매도 시스템** - 건물 판매 프로세스
3. **거래 검증 로직** - 유효성 검사

5. **거래 기록 시스템** - Transaction 로깅

## 1. 매수 시스템 (Buy System)

### 1.1 매수 가능 조건

건물을 매수하려면 다음 조건을 **모두** 만족해야 합니다:

| 조건 | 검증 내용 | 에러 메시지 |
|-----|---------|-----------|
| **1. 매물 상태** | `building.is_for_sale == True` | "매물로 나온 건물이 아닙니다" |
| **2. 소유권** | `building.owner != "player"` | "이미 소유한 건물입니다" |
| **3. 자금 충분** | `필요 자금 <= 사용 가능 자금` | "자금이 부족합니다" |

#### 필요 자금 계산

```python
필요 자금 = 건물 가격 + 취득세
취득세 = 건물 가격 × 0.01

# 예시
건물 가격 = 10억
취득세 = 1천만 원
필요 자금 = 10.1억
```

#### 사용 가능 자금 계산

플레이어는 **현금 + 대출 가능액**을 사용할 수 있습니다:

```python
사용 가능 자금 = 현금 + 대출 가능 잔여액
대출 가능 잔여액 = (보유 건물 평가액 × LTV) - 현재 대출 잔액

# 예시
현금 = 2억
보유 건물 평가액 = 30억
LTV = 70%
현재 대출 = 15억

대출 가능 잔여액 = (30억 × 0.7) - 15억 = 6억
사용 가능 자금 = 2억 + 6억 = 8억
```

### 1.2 매수 프로세스

#### Step 1: 건물 선택
- 플레이어가 지도에서 건물 클릭
- `is_for_sale == True`인 건물만 "매수" 버튼 활성화

#### Step 2: 건물 정보 확인
건물 상세 패널에 다음 정보 표시:

```
┌─────────────────────────────────┐
│  역삼 오피스텔 A동               │
│  주거 · C급 · 역세권             │
├─────────────────────────────────┤
│  매매가: 7.5억                   │
│  취득세: 750만 원 (1%)           │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  총 필요 자금: 7.575억           │
│                                 │
│  예상 월 임대료: 312만 원        │
│  연 수익률: 4.95%                │
├─────────────────────────────────┤
│  💰 보유 현금: 2억               │
│  💳 대출 가능: 6억               │
│  ✅ 사용 가능: 8억               │
├─────────────────────────────────┤
│  [  매수하기  ]  [  취소  ]      │
└─────────────────────────────────┘
```

#### Step 3: 자금 조달 방법 선택

플레이어는 **현금 우선 사용 + 부족분 대출 자동 실행** 방식:

```python
필요 자금 = 7.575억
보유 현금 = 2억

if 필요 자금 <= 보유 현금:
    # 현금만으로 충분
    현금 사용 = 필요 자금
    대출 실행 = 0
else:
    # 현금 + 대출 사용
    현금 사용 = 보유 현금
    대출 실행 = 필요 자금 - 보유 현금
    
# 예시
현금 사용 = 2억
대출 실행 = 5.575억 (자동 대출)
```

**MVP에서는 자동 대출** (플레이어가 대출 금액을 선택하지 않음)
- Phase 2+에서 수동 대출 금액 조절 UI 추가 고려

#### Step 4: 최종 확인 팝업

대출이 발생하는 경우 경고 표시:

```
┌─────────────────────────────────┐
│  ⚠️ 매수 확인                    │
├─────────────────────────────────┤
│  건물: 역삼 오피스텔 A동          │
│  총 비용: 7.575억                │
│                                 │
│  💰 현금 사용: 2억               │
│  💳 대출 실행: 5.575억           │
│                                 │
│  ⚠️ 대출 이자 (월): 232만 원    │
│  (연 5% 가정)                    │
│                                 │
│  매수 후 상태:                   │
│  - 현금: 0원                     │
│  - 총 부채: 20.575억             │
│  - 순 현금 흐름: +80만 원/월     │
│    (임대료 312만 - 이자 232만)   │
├─────────────────────────────────┤
│  [  확인  ]     [  취소  ]       │
└─────────────────────────────────┘
```

#### Step 5: 거래 실행

**거래 실행 로직**:
1. 자금 검증 (재확인)
2. 현금 및 대출 금액 계산
3. 플레이어 자금 차감 및 대출 실행
4. 건물 소유권 이전 (`owner = "player"`)
5. 거래 기록 생성
6. 성공 메시지 표시

### 1.3 매수 후 즉시 효과

| 효과 | 내용 |
|-----|------|
| **소유권 이전** | `building.owner = "player"` |
| **매물 상태 해제** | `building.is_for_sale = False` |
| **현금 감소** | 총 필요 자금만큼 차감 |
| **부채 증가** | 대출 실행 시 `total_debt` 증가 |
| **월 수입 증가** | 다음 월부터 임대료 수입 |
| **월 지출 증가** | 대출 시 다음 월부터 이자 지출 |

### 1.4 매수 제한 사항 (MVP)

| 제한 | 내용 | Phase |
|-----|------|-------|
| **동시 거래** | 1개월에 여러 건물 매수 가능 | MVP ✅ |
| **보유 건물 수** | 제한 없음 | MVP ✅ |
| **지역 제한** | 역삼동만 (지도 범위 내) | MVP ✅ |
| **네고시에이션** | 가격 협상 불가 (시세 그대로) | Phase 3+ |

## 2. 매도 시스템 (Sell System)

### 2.1 매도 가능 조건

| 조건 | 검증 내용 | 에러 메시지 |
|-----|---------|-----------|
| **1. 소유권** | `building.owner == "player"` | "본인 소유 건물이 아닙니다" |
| **2. 리모델링 중 아님** | `building.is_under_renovation == False` | "리모델링 중인 건물은 매도할 수 없습니다" |

### 2.2 매도 방식

#### A. 즉시 매도 (Instant Sale) - **MVP 구현**

시스템에 **즉시 매각**하는 방식:

```python
즉시 매도 수익 = 현재 시세 × 0.95
```

**특징**:
- ✅ 즉시 현금화
- ✅ 확실한 거래
- ❌ 5% 손해 (시세의 95%)

#### B. 매물 등록 (List for Sale) - **Phase 2+ 구현**

희망 가격을 설정하고 시장에 등록:

```python
희망 가격 설정 (플레이어 입력)
등록 기간 = 1~6개월 (시장 상황에 따라 변동)
판매 확률 = f(시세 대비 희망가 비율)
```

**특징**:
- ✅ 시세 그대로 또는 그 이상 받을 가능성
- ❌ 판매 시점 불확실
- ❌ 판매 전까지 임대료는 계속 수령

**MVP에서는 제외**, Phase 2 이후 추가

### 2.3 즉시 매도 프로세스 (MVP)

#### Step 1: 건물 선택
- 플레이어가 보유 건물 클릭
- "매도" 버튼 활성화

#### Step 2: 매도 정보 확인

```
┌─────────────────────────────────┐
│  역삼 오피스텔 A동               │
│  주거 · C급 · 역세권             │
├─────────────────────────────────┤
│  💰 매입가: 7.5억 (2004.03)     │
│  📈 현재 시세: 8.2억 (+9.3%)     │
│  💵 즉시 매도가: 7.79억 (95%)    │
│                                 │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  📊 손익 계산                    │
│  - 매도 수익: 7.79억             │
│  - 매입 비용: 7.575억            │
│    (매입가 7.5억 + 취득세 750만) │
│  - 순이익: +2,150만 원 (+2.8%)   │
│                                 │
│  📅 보유 기간: 8개월             │
│  💸 누적 임대료: 2,496만 원      │
│  💳 누적 이자: 1,392만 원        │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  🏆 총 실현 손익: +3,254만 원    │
│    (매매차익 + 임대료 - 이자)    │
├─────────────────────────────────┤
│  [  즉시 매도  ]  [  취소  ]     │
└─────────────────────────────────┘
```

#### Step 3: 대출 상환 확인

만약 이 건물이 대출 담보인 경우:

**대출 한도 재계산 로직**:
```
매도 후 남은 건물 가치 = 총 건물 가치 - 매도 건물 가치
새 대출 한도 = 남은 건물 가치 × 0.7

if 현재 대출 > 새 대출 한도:
    강제 상환액 = 현재 대출 - 새 대출 한도
    실제 현금 증가 = 매도 수익 - 강제 상환액
```

**경고 팝업 예시**:

```
┌─────────────────────────────────┐
│  ⚠️ 대출 상환 필요               │
├─────────────────────────────────┤
│  이 건물을 매도하면, 대출 한도가  │
│  초과되므로 일부 상환이 필요합니다 │
│                                 │
│  매도 수익: 7.79억               │
│  강제 상환: 3억                  │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  실제 현금 증가: 4.79억          │
│                                 │
│  계속하시겠습니까?               │
├─────────────────────────────────┤
│  [  확인  ]     [  취소  ]       │
└─────────────────────────────────┘
```

#### Step 4: 거래 실행

**거래 실행 로직**:
1. 소유권 검증
2. 매도 수익 계산 (시세 × 0.95)
3. 대출 강제 상환액 계산
4. 실제 현금 증가 = 매도 수익 - 강제 상환액
5. 플레이어 상태 업데이트 (현금, 부채, 소유 건물)
6. 건물 소유권 이전 (`owner = "NPC"`)
7. 거래 기록 생성
8. 성공 메시지 표시

### 2.4 매도 후 즉시 효과

| 효과 | 내용 |
|-----|------|
| **소유권 이전** | `building.owner = "NPC"` |
| **현금 증가** | 매도 수익 - 강제 상환액 |
| **부채 감소** | 강제 상환액만큼 감소 (발생 시) |
| **월 수입 감소** | 다음 월부터 임대료 수입 없음 |
| **월 지출 감소** | 대출 상환 시 이자 감소 |

### 2.5 매도 제한 사항 (MVP)

| 제한 | 내용 | Phase |
|-----|------|-------|
| **리모델링 중** | 매도 불가 (공사 완료 후 가능) | MVP ✅ |
| **최소 보유 기간** | 제한 없음 (즉시 매도 가능) | MVP ✅ |
| **매도 후 재구매** | 즉시 재구매 불가 (1개월 후 재등장) | Phase 2+ |

## 3. 거래 검증 로직

### 3.1 공통 검증 규칙

모든 거래는 다음을 검증해야 합니다:

**검증 항목**:
1. 게임 상태 확인 (게임 오버 여부)
2. 건물 존재 확인
3. 거래 유형별 검증:
   - **매수**: 매물 상태, 소유권, 자금 충분 여부
   - **매도**: 소유권, 리모델링 중 아닌지

### 3.2 예외 상황 처리

| 상황 | 처리 방법 |
|-----|---------|
| **현금 음수** | 허용 (일시적), 단 3개월 연속 시 경고 |
| **대출 한도 초과** | 거래 거부 |
| **건물 가격 0원** | 거래 거부 (데이터 오류) |
| **동시 거래 충돌** | 실시간 게임이므로 발생 안 함 (일시정지 중 거래) |

## 4. 거래 UI/UX 플로우

### 4.1 매수 플로우 (사용자 관점)

```
1. 지도에서 건물 클릭
   ↓
2. 건물 상세 패널 열림
   - 매물이면 "매수" 버튼 활성화
   - 아니면 "매물 아님" 표시
   ↓
3. "매수" 버튼 클릭
   ↓
4. 최종 확인 팝업 (대출 경고 포함)
   ↓
5. "확인" 클릭
   ↓
6. 거래 실행
   - 성공: 성공 메시지 + 소유권 표시 업데이트
   - 실패: 에러 메시지 팝업
```

### 4.2 매도 플로우 (사용자 관점)

```
1. 보유 건물 클릭 (지도 또는 자산 패널)
   ↓
2. 건물 상세 패널 열림
   - "매도" 버튼 활성화
   ↓
3. "매도" 버튼 클릭
   ↓
4. 매도 정보 확인 창
   - 손익 계산 표시
   - 대출 상환 필요 시 경고
   ↓
5. "즉시 매도" 클릭
   ↓
6. 거래 실행
   - 성공: 성공 메시지 + 현금 증가 애니메이션
   - 실패: 에러 메시지 팝업
```

### 4.3 시각적 피드백

| 피드백 요소 | 구현 |
|----------|------|
| **소유 건물 표시** | 바닥 타일 초록색 (Mint) |
| **매물 표시** | 건물 위에 `$` 아이콘 플로팅 |
| **마우스 오버** | 바닥 타일 파란색 + 툴팁 |
| **거래 성공** | 현금 증가/감소 애니메이션 (상단 바) |
| **에러** | 빨간 테두리 + 경고 아이콘 |

## 5. 거래 기록 시스템

### 5.1 Transaction 객체 생성

모든 거래는 `Transaction` 엔티티로 기록됩니다:

**기록 항목**:
- 거래 ID (UUID)
- 거래 시점 (게임 내 월)
- 거래 유형 (매수/매도)
- 건물 ID
- 금액 (양수: 수입, 음수: 지출)
- 설명 (건물명 + 거래 내용)

### 5.2 거래 내역 조회

```

│  📊 거래 내역 (최근 10건)         │

│  2004.09  역삼 오피스텔 A동 매수 │

│  2006.01  강남 상가 B동 매수     │
│           -12.12억               │
└─────────────────────────────────┘
```

### 5.3 통계 제공 (Phase 2+)

- 총 거래 횟수

- 최고 수익률 거래
- 총 실현 손익

## 6. 특수 상황 처리

## 8. 밸런싱 고려사항

### 8.1 즉시 매도 5% 손해의 의미

```
시세 10억 건물 즉시 매도 = 9.5억 수익
매수 시 취득세 1% = 1천만 원 손실

손익분기점 = 10억 × 1.01 (매입) → 9.5억 (매도)
실질 손실 = -6.1% (매도-재매수 사이클)
```

**설계 의도**: 빈번한 단타 거래 방지, 중장기 보유 유도

### 8.2 대출 레버리지 전략

매수 시 대출을 활용하면:
- ✅ 적은 현금으로 큰 자산 확보
- ✅ 임대료 > 이자 시 순이익
- ❌ 시세 하락 시 손실 확대
- ❌ 유동성 위기 가능

**설계 의도**: 리스크-리턴 균형, 전략적 선택 유도
