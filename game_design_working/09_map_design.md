## 1. 그리드 시스템

### 1.1 기본 구조

게임 맵은 **정사각형 그리드**로 구성됩니다:

```
맵 크기 = 그리드 가로 × 그리드 세로
좌표 = (x, y) 형식, 0부터 시작
```

| 항목 | MVP 값 | Phase 2+ |
|-----|--------|----------|
| **그리드 크기** | 20 × 20 | 50 × 50 |
| **타일 크기** | 1 × 1 (기본 단위) | 동일 |
| **총 타일 수** | 400개 | 2,500개 |

**MVP 간소화**: 역삼동 한 개 지역만 구현

### 1.2 좌표 시스템

```
좌표 원점: 왼쪽 상단 (0, 0)
x축: 오른쪽으로 증가
y축: 아래쪽으로 증가

예시:
(0, 0)  (1, 0)  (2, 0)  ...
(0, 1)  (1, 1)  (2, 1)  ...
(0, 2)  (1, 2)  (2, 2)  ...
...
```

### 1.3 그리드 밀도

타일 한 칸의 의미:
- **실제 크기**: 약 50m × 50m (개념적)
- **건물 크기**: 1×1 ~ 3×3 타일
- **도로 폭**: 1타일

## 2. 타일 시스템

### 2.1 타일 종류

각 타일은 **지형 타입**을 가집니다:

| 타일 타입 | 코드 | 건물 배치 가능 | 설명 |
|---------|------|--------------|------|
| **빈 땅** | `empty` | ✅ | 건물 건설 가능 |
| **도로** | `road` | ❌ | 이동 경로 |
| **공원** | `park` | ❌ | 주변 건물 입지 보너스 |
| **지하철역** | `subway` | ❌ | 주변 건물 입지 보너스 |
| **수변** | `water` | ❌ | 장식용 (Phase 2+) |

**MVP 제한**: `empty`, `road`, `park`, `subway` 만 사용

### 2.2 타일 오버레이

타일 위에 추가로 표시되는 정보:

| 오버레이 | 설명 | 효과 |
|---------|------|------|
| **지하철역 마커** | 🚇 아이콘 | 200m 반경 역세권 |
| **공원 경계선** | 녹색 테두리 | 인접 타일 입지 보너스 |
| **건물 그림자** | 반투명 영역 | 건물 크기 표시 |

### 2.3 Tile 엔티티 구조

`05_entities.md`에 정의된 `Tile` 엔티티 참조:

```
Tile {
  position: (x, y)
  terrain_type: "empty" | "road" | "park" | "subway"
  building_id: str | None
  overlay: str | None
  district: "역삼동"
}
```

## 3. 건물 배치 원칙

### 3.1 건물 크기 시스템

건물은 **여러 타일을 차지**할 수 있습니다:

| 건물 크기 | 타일 수 | 예시 |
|---------|--------|------|
| **소형** | 1 × 1 (1칸) | 주거 C급, 작은 상가 |
| **중형** | 2 × 2 (4칸) | 주거 B급, 상업 B급 |
| **대형** | 3 × 3 (9칸) | 오피스 A급 (Phase 2+) |

**MVP 간소화**: 모든 건물 1 × 1 크기로 고정

### 3.2 배치 규칙

| 규칙 | 설명 |
|-----|------|
| **겹침 금지** | 건물이 차지하는 타일은 다른 건물과 겹칠 수 없음 |
| **도로 인접** | 건물은 최소 한 면이 도로와 인접해야 함 (Phase 2+) |
| **입지 고려** | 지하철역, 공원 근처 건물은 입지 계수 적용 |

### 3.3 Building 위치 정보

`05_entities.md`의 `Building` 엔티티에 위치 저장:

```
Building {
  position: (x, y)         # 좌상단 기준 좌표
  size: (width, height)    # 타일 개수
}
```

**예시**: 
- 1×1 건물이 (5, 3) 위치 → 타일 (5, 3) 차지
- 2×2 건물이 (5, 3) 위치 → 타일 (5,3), (6,3), (5,4), (6,4) 차지

### 4.1 맵 개요

| 항목 | 값 |
|-----|-----|
| **지역명** | 역삼동 |

```
│  ═══════════════════════      │  ═ = 도로
│  □ □ □ 🚇 □ □ □ □ 🏢 □      │  🚇 = 지하철역 (선릉역)
│  □ 🏢 ═══════ 🏢 □ □ □      │  □ = 빈 땅
│  □ □ □ □ □ ═══════ □ □      │
│  □ 🏢 □ □ □ □ □ □ 🏢 □      │
│  ...                          │
└─────────────────────────────┘
```

실제 좌표는 `data/map_data.json`에 정의 (예정)

### 4.3 건물 분포 (MVP)

건물은 다음 원칙으로 배치:

| 건물 | 수량 | 입지 | 특징 |
|-----|------|------|------|
| **역세권 건물** | 2~3개 | 지하철역 200m | 입지 계수 1.3 |
| **공원 인접** | 1~2개 | 공원 경계 | 입지 계수 1.15 |
| **일반 건물** | 2~5개 | 일반 위치 | 입지 계수 1.0 |

**총 5~10개** 건물로 MVP 구성

### 4.4 건물 타입 분포

| 타입 | 수량 | 비율 |
|-----|------|------|
| **주거** | 3~4개 | 40~50% |
| **상업** | 2~3개 | 30~40% |
| **오피스** | 1~2개 | 10~20% |

### 4.5 등급 분포

| 등급 | 수량 | 비율 |
|-----|------|------|
| **C급** | 4~5개 | 50~60% |
| **B급** | 2~3개 | 30~40% |
| **A급** | 0~2개 | 0~20% |

### 8.2 건물이 차지하는 타일 계산

```python
def get_occupied_tiles(building):
    """건물이 차지하는 모든 타일 좌표 반환"""
    x, y = building.position
    w, h = building.size
    
    occupied = []
    for dy in range(h):
        for dx in range(w):
            occupied.append((x + dx, y + dy))
    
    return occupied
```

### 8.3 입지 보너스 판정

```python
def calculate_location_bonus(building, map_data):
    """건물의 입지 보너스 계산"""
    x, y = building.position
    
    # 지하철역과의 거리
    for subway in map_data.landmarks['subway']:
        distance = calculate_distance((x, y), subway.position)
        if distance <= 4:  # 200m = 4타일
            return 'subway_nearby'
    
    # 공원 인접 확인
    for park_tile in map_data.landmarks['park'].area:
        if is_adjacent((x, y), park_tile):
            return 'park_nearby'
    
    return 'normal'
```

## 부록: 맵 제작 가이드라인

### A. 건물 배치 원칙

1. **밀집도**: 너무 빽빽하지 않게 (공백 30~40%)
2. **입지 분산**: 역세권/공원/일반 골고루
3. **시각적 균형**: 한쪽으로 치우치지 않게
4. **접근성**: 모든 건물이 도로와 연결

### B. 현실 반영

- **선릉역**: 역삼동의 실제 지하철역
- **선정릉**: 실제 존재하는 역사 유적
- 건물 이름은 가상이지만 **현실적인 네이밍** 사용

### C. 게임성 고려

- 다양한 가격대 건물 혼재
- 초보자가 구매 가능한 저가 건물 포함
- 후반부 목표가 될 고가 건물 포함
